# Phase 0 — Start

Goal: get to the first useful output as fast as possible. Nothing here should feel like setup to the user.

1. **Start from what they asked.** If their message names a goal, a surface or a design of their own, go to phase 1 at the step it lets you skip to (phase 1, §2). If it asks for nothing specific and `.levered/state.json` exists, follow **Resuming** in [../references/state.md](../references/state.md): say in one or two lines where things stand and continue there. Don't start over.
2. **Nothing to install yet.** The first findings need only reading the code: not the CLI, not sign-in, not the project's dependencies. Dependencies come at "build them" (phase 2), the CLI at launch (phase 3).
3. **Otherwise, settle the goal first:** the goal card, with your best guess first (phase 1, §2).
4. **Sign-in is offered, not required.** For a returning user, check `levered whoami` if the CLI is there and use their knowledge base. For a new one, offer sign-in only when it adds something specific (their connected analytics), as an option on the next-step card; going live is the first step that needs it (phase 3, §1).
